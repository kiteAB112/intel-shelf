# 来源维护规则

## 准入

档案记录官方入口、类别、用途、性质、限制、获取方式、发现路径及文档核验日期。候选结构检查通过不能自动转为正式接受；人工根据实际调查评价原始证据、覆盖、重复引用、准确性、发布延迟及使用条件。

同一来源的 RSS/API 是不同渠道，不算独立佐证。研究博客不能替代厂商修复公告。普通黑名单不直接证明 CVE 与活动关联。

## 自动观察

- access：reachable / fetch-failed / needs-auth-or-access-review。
- content：valid / not-validated / not-checked。
- freshness：within-window / review / unknown。日期取 feed 条目或 KEV 发布字段，不取 HTTP Date 代替。
- checked_at、last_success_at、latest_item_at、last_content_change_at 分开。初次获取不知道此前何时变化。
- 无端点的待接入来源只记录 evaluated_at，不伪造数据请求时间 checked_at。
- 主清单须同时满足端点存在、最近检查未超过 max(24小时, 两倍检查间隔)、获取与解析成功、非空、无当前告警；RSS 还需能提取文章标题与引用链接。其余单列，不计为可读取。重新生成目录会检查旧结果是否过期。
- 空数据、数量低于上次一半或超过两倍、日期倒退、未来日期、超出复核阈值生成异常；连续三次失败追加 repeated-failure，恢复后清除当前异常、保留历史。
- 无条目时间的列表跨次比较摘要；长期不变仅提示复核，不直接淘汰。NVD 单记录探针不能验证全量新鲜度。
- 失败保留上次成功的计数/摘要，用 last_success_at 识别历史值；当前格式和新鲜度标为未验证/未知。

阈值为本项目复核策略，不是来源更新承诺；低频报告允许更长窗口。自动队列只保存当前异常；人工调查反馈写入独立 data/feedback.json，不被自动检查覆盖。

## 恶意指标核验

TweetFeed按无表头CSV读取，支持国际化域名；保留报告时间/发布者/引用与类型计数，剔除不合规指标并统计（超过5%触发复核）。Feodo按last_online判断时效，不采信旧记录的online为当前状态。C2 CSV无日期则保留未知，不从文件获取时间倒推出观测时间。少量示例去武器化，不访问指标。每个来源计一次，跨类别不重复计总数。

可读取不代表允许公司使用。C2IntelFeeds的非商业限制必须显示，不能作为企业集成的默认源；TweetFeed只接入native feed，external补充数据条款另核对。详细判断见docs/ioc-source-review.md。

空数据首先是复核信号，不自动意味着上游故障。官方可能明确当前没有对应威胁。经核验调整use_status=historical-only的来源，即使以后某次返回非空且格式正确，也不能自动回到当前可用清单；须重新审核用途。

## 运行与审核

当前只手动触发，脚本按每源间隔判断。禁止并发执行，避免覆盖状态。未来云端与本地状态需独立保存。暂无主动通知与历史自动清理。来源调整须给理由、引用与具体修改；用户已授权的本地MVP范围内，由执行AI核验后直接完成并记录，不重复请求常规确认。自动检查脚本自身不擅自变更用途。上游issue只准备草稿。

网络传输错误最多两次，逐次保留时间与错误；HTTP 错误不自动重试，失败次数按检查轮次计。重试后成功也不抹除先前尝试或历史故障。可读取是一次入口实测，不是长期稳定性或质量认证。
